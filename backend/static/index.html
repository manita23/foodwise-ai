Demand Forecast

IBM Granite TTM (Tiny Time Mixers) · zero-shot multivariate forecasting

🤖 How IBM Granite TTM works

FoodWise AI uses IBM Granite Tiny Time Mixers (TTM) — a family of compact, pre-trained models for multivariate time-series forecasting from IBM Research. Available via the watsonx.ai Forecast API.


• Model: ibm/granite-ttm-512-96-r2 — requires 512 historical data points, generates a 96-point forecast horizon

• Zero-shot: no fine-tuning required — runs directly on your consumption history

• Multivariate: can forecast multiple food items simultaneously using correlated patterns

AI Domains

All IBM Granite capabilities integrated in FoodWise AI

📈

Time-Series Forecasting

IBM Granite TTM (granite-ttm-512-96-r2) forecasts future meal demand from historical consumption using the watsonx.ai Forecast API. Zero-shot — no training required.

Confidence: High · API: /ml/v1/wx_data/time_series/forecast

💬

Conversational Q&A

IBM Granite 3.3 8b Instruct answers natural-language questions about food safety, waste reduction and catering policy via the watsonx.ai Chat API.

Model: granite-3-3-8b-instruct · API: /ml/v1/text/chat

📄

RAG — Policy Retrieval

Retrieval-Augmented Generation using granite-embedding-278m-multilingual embeds food-safety and catering policy documents. Answers are grounded, with source citations.

Store: Chroma (local) / Elasticsearch (prod) · API: /ml/v1/text/embeddings

⚠️

Human-in-the-Loop Oversight

Every AI recommendation is written as a pending record. No kitchen action is taken automatically. A human administrator must approve or reject each recommendation before it takes effect.

Enforced at: Approval Queue · Status: pending → approved/rejected

🔮

Surplus Estimation

Computes predicted surplus as forecast − headcount × portion_weight. Flags meals with >5 kg projected surplus for proactive redistribution planning.

Derived from Granite TTM output · displayed on Forecast page

📊

Waste Trend Analysis

Aggregates historical waste records by day and category. Detects anomalies and patterns — e.g. spoilage spikes on weekends, or plate waste trending up for a specific item.

Source: PostgreSQL aggregation · Phase 2: AI anomaly detection

Data Flow

Kitchen Data (CSV / manual entry)
   → PostgreSQL (meals · consumption · waste_records)
      → ForecastingService → watsonx.ai Forecast API (Granite TTM)
      → RAGRetriever → watsonx.ai Embeddings API (Granite Embed)
          → Chroma vector store → top-k chunks
      → GraniteChatService → watsonx.ai Chat API (Granite 3.3 8b)
          → Answer + RECOMMENDATION: block
              → Approval Queue (human sign-off required)
                  → status: approved / rejected

Settings

Application configuration and alert thresholds

🤖 AI Configuration

To switch from mock mode to real IBM Granite calls, set the following in foodwise-ai/.env: 
AI_MODE=real
WATSONX_API_KEY=your-ibm-cloud-api-key
WATSONX_PROJECT_ID=your-watsonx-project-id
WATSONX_URL=https://us-south.ml.cloud.ibm.com

# Granite models (already set to correct IDs)
GRANITE_CHAT_MODEL=ibm/granite-3-3-8b-instruct
GRANITE_TTM_MODEL=ibm/granite-ttm-512-96-r2
GRANITE_EMBED_MODEL=ibm/granite-embedding-278m-multilingual

Get your API key at cloud.ibm.com/iam/apikeys · Project ID is in your watsonx.ai project URL.
